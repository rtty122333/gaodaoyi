# 高岛易断 · Cardputer ADV 查询器

把《高岛易断》（高岛吞象 / Takashima Ekidan，明治时代公版文本）全文装进 Cardputer ADV，
开机进主菜单，三件事任选：

- **数字起卦占卜** —— 自己报 9 位数字（三组三位数），按傅佩荣《易经入门 17 讲》的数字卦法
  起出本卦 / 动爻 / 之卦，直接落到知识库里对应的断语上；
- **时间起卦** —— 按梅花易数「年月日时起例」，输入起卦时刻的**公历**年月日时（10 位数字），
  程序换算成**农历**后取「年支数 + 农历月 + 农历日 + 时辰数」定卦；
- **高岛易断原文** —— 按编号查任意一卦，逐层下钻到「全卦总论」或某一爻的详细占断解读。

中文在 1.14" 屏上实时渲染、可滚动。

## 开机流程
```
① 主菜单   1  数字起卦占卜
   │       2  时间起卦
   │       3  高岛易断原文
   ├─ 选 1 → 数字输入（报 9 位）  → 起卦结果 ─ Enter ─┐
   ├─ 选 2 → 时间输入（年月日时） → 起卦结果 ─ Enter ─┤
   └─ 选 3 → 选卦列表 ─ Enter ─┐                    │
                               ▼                    ▼
                          ② 详目（本卦 7 个条目，起卦时光标自动停在动爻）
                               │  Enter
                               ▼
                          ③ 正文（爻题 → 象传 → 高岛释义 → 占 → 占例），可滚动
```

   │      本卦 7 个条目，右侧卦象高亮当前那一爻
   │      条目名一行放不下时：仅"当前选中"那条缓慢平滑滚动，其余截断显示
   │      1 全卦总论      ← 卦名释义 / 卦辞 / 彖传 / 大象 / 总占
   │      2 初九 潜龙勿用
   │      3 九二 见龙在田，利见…   ← 未选中：截断 + 省略号
   │      ...

③ 正文   所选条目的完整解读（爻题 → 象传 → 高岛释义 → 占 → 占例），可滚动

层级命名：第②层叫「**详目**」——取「本卦详目」之意，即一卦之下的细目；
七个条目沿用易学原生的「全卦 + 六爻」叫法，爻名（初九/六二/上六…）本身就是最准确的目录名。

## 数字卦起卦（傅佩荣《易经入门 17 讲》随机数起卦法）
主菜单选「数字起卦占卜」，**自己报 9 位数字**（三组三位数，任意一位都可以是 0）：

| 组 | 输入 | 运算 | 结果 | 除尽时 |
|---|---|---|---|---|
| 第一组 | 第 1–3 位 | ÷ 8 取余 | **下卦**（内卦） | 记 8 → 坤 |
| 第二组 | 第 4–6 位 | ÷ 8 取余 | **上卦**（外卦） | 记 8 → 坤 |
| 第三组 | 第 7–9 位 | ÷ 6 取余 | **动爻**（变爻） | 记 6 → 上爻 |

余数对照**先天八卦数**：乾 1、兑 2、离 3、震 4、巽 5、坎 6、艮 7、坤 8。

> ⚠️ 两个最容易写错的地方：
> 1. **第一组是下卦，第二组才是上卦**（由下往上写），与常见"先上后下"的报数法相反；
> 2. 先天八卦数（乾 1…坤 8）**不是**代码里那套三爻 bit 值（乾 7、兑 3、离 5、震 1、
>    巽 6、坎 2、艮 4、坤 0），两套编号必须显式转换（`XT_BITS[9]`）。

### 关于「三位数」这条要求的松紧（本实现：放开）
傅佩荣原设定是**三组三位数**（首位非 0）。理由是：一位数、两位数的余数太容易心算，
"主观目的性非常强，那就不是问天意，而是看人意"；三位数要先做一次除法，随意性够高。
数字越小，取余越没有遮蔽作用：

| 这一组的值 | ÷ 8（下卦/上卦） | ÷ 6（动爻） |
|---|---|---|
| `004` = 4 | 余 4，**余数就是数字本身** | 余 4，同上 |
| `047` = 47 | 余 7，要算一下但能心算 | — |
| `431` | 商 53 余 7，必须列竖式 | — |

本实现按使用习惯**放开了首位 0 的限制**：9 位里任何一位都能填 0（含 `004`、甚至 `000000000`
→ 坤为地 上爻动）。代价就是上表第一行那种情况——结果可被一眼预判，随意性打折。
若要恢复严格模式，在 `inputAppend()` 里加回首位判断即可：

```cpp
if (digits.length() % 3 == 0 && c == '0') return;    // 每组首位非 0
```

（也因此三组数整体取模的分布是均匀的：八个余数各约 12.5%、六个动爻各约 16.7%；
实测 100 万次随机覆盖全部 64 卦。）

输入页**刻意不显示任何换算结果**（卦名 / 余数 / 爻位），只报「还需输入 N 位」——
边输边看到卦象会给报数者心理暗示，破坏"随意报数"的初衷；换算明细统一到起卦结果页才揭晓。

起卦结果页列出三组数的除法明细 + 本卦 + 动爻与之卦，右侧六爻图把**动爻标红**。

### 「之卦」是什么
「之」在古汉语里是**动词**，意思是「往、到、变往」。所以「某卦之某卦」读作
「由某卦变到某卦」——**之卦就是动爻变化之后得到的那一卦，古人多称「变卦」**。

变法只有一条规则：**把动爻那一爻的阴阳翻过来**（阳变阴、阴变阳），其余五爻一律不动。

| | 含义 | 例（观梅占：泽火革，初爻动） |
|---|---|---|
| **本卦** | 事情的现状 / 起因 | 泽火革 ䷰（上兑泽、下离火） |
| **动爻** | 转变的枢机，断卦的重心 | 初九 —— 由阳变阴 |
| **之卦** | 事情的趋向 / 结果 | 初爻一翻，下卦离（火）成艮（山），上卦泽不变 → 泽山咸 ䷞ |

所以断卦看的就是「**本卦 + 动爻爻辞 + 之卦**」这三件套。高岛断卦尤重动爻，
故按 `Enter` 进本卦、`b` 进之卦，**光标都自动停在该动爻那一条上**。

> 屏底那行 `Enter:本卦 b:之卦 r:改依据 m:返回` 是**按键提示**（`b` 是键盘上的 b 键），
> 不是卦名也不是代号。

`_cast_check.py` 是这套换算的回归脚本：校验 64 卦六爻解析是 0..63 的双射、公开示例
（431/379/847 → 火山旅初爻；493/809/793 → 天风姤初爻；130/174/314 → 水泽节二爻）全部命中。

## 时间起卦（梅花易数「年月日时起例」）
主菜单选「时间起卦」，输入起卦时刻的 **公历年月日时共 10 位数字**（年 4 位 + 月 2 位 + 日 2 位 + 时 2 位）。

![时间起卦界面](_time_preview.png)

### 三个数都取农历（关键）
原书（《梅花易数》卷一）：

> 先将年月日之数除八，得余数为上卦；再将年月日时之数除八，得余数为下卦；
> 又将年月日时之数除六，得余数为动爻。

原书说的「月、日」是**农历**月日，各家讲义都点明了（"月数直接以**农历之月数**计，
日数直接以**农历日数**计"）。所以流程是：

```
输入公历 ──solarToLunar()──> 农历 年/月/日 ──┬─ 年支数 = 由农历年换算
                                            ├─ 月数   = 农历月序
                                            ├─ 日数   = 农历日序
                                            └─ 时数   = 由 0–23 时换算的时辰序数
```

| 项 | 算式 | 除尽时 |
|---|---|---|
| **上卦**（外卦） | (年支数 + **农历月** + **农历日**) ÷ 8 取余 | 记 8 → 坤 |
| **下卦**（内卦） | (年支数 + **农历月** + **农历日** + 时数) ÷ 8 取余 | 记 8 → 坤 |
| **动爻** | (年支数 + **农历月** + **农历日** + 时数) ÷ 6 取余 | 记 6 → 上爻 |

余数同样对照先天八卦数（乾 1…坤 8），与数字卦共用 `XT_BITS` 转换表。

- **年支数** = 地支序数 `子1 丑2 寅3 卯4 辰5 巳6 午7 未8 申9 酉10 戌11 亥12`，
  由**农历年**换算 `(年 − 4) mod 12 + 1`（公元 4 年 = 甲子）。
  农历年以正月初一分界 —— 公历 1–2 月的日期可能还属上一个农历年，程序自动处理。
- **时数** = 时辰序数，由输入的 0–23 时换算：`23~00 时=子(1)`、`01~02=丑(2)`、…、`21~22=亥(12)`。

输入页把换算出的农历日期**实时回显**出来（如 `农历 丙午年八月初七 申时`），
起卦结果页也把「公历 → 农历」摊开 —— 公式用的正是这几个数，可逐项核对。

### 农历表（1900–2100）
`src/lunar_data.h` 每年一个 `uint32_t`（201 项，约 800 字节）：

```
bit 0..3   闰月月份 (0 = 该年无闰月)
bit 15..4  十二月大小, bit15=正月 … bit4=十二月 (1 = 30 天, 0 = 29 天)
bit 16     闰月大小 (1 = 30 天, 0 = 29 天)
```

起点 公历 1900-01-31 = 农历 1900 年正月初一，**早于这天的日期无法起卦**（输入页会拦）。

`_lunar_table.py` 生成这张表并做四方验证：

| 来源 | 角色 |
|---|---|
| **lunar_python**（寿星天文历，天文算法） | **主来源** |
| lunarcalendar（香港天文台数据） | 校验：逐日比对 73384 天，仅 2089 / 2097 年共 60 天不一致 |
| lunardate（Lee & Yeung 经典查表） | 校验：仅 1933 / 1954 / 1978 / 2057 四年差一天 |
| **ephem**（实算朔时刻） | **裁决**：对全部 **2486 个农历月初一**逐个验「初一 = 朔所在之日」 |

裁决结果：**0 个超出 ΔT 不确定区**。三处争议都判给主来源 —— 1933/1954/1978 是经典表错一天；
2089 是香港天文台数据错两天（朔在 `2089-09-04 23:57`，初一就该是 9/4）。
另有 2 个初一（1906-04-24、2057-09-29）的朔落在午夜前 8 分钟内，属 ΔT 模型不确定区，
无法裁决，采信主来源。

> 一个容易踩的坑：**1929 年以前中国历书用北京地方平时**（东经 116°24′ ≈ UTC+7:45:40），
> 不是东八区。拿 UTC+8 去验 1914 / 1916 / 1920 的朔，会平白差出一整天。

### 与「严格古法」的差别
只剩一处：**年支取农历年的年支**（正月初一换年）。另有一派主张按**立春**分界，
那是八字 / 五运六气的干支口径，梅花起卦传统用农历年 —— 本实现从传统。

子时跨 23:00–00:59 两个日历日，传统把 23:00 之后算作**次日子时**，而日数进公式、会影响结果。
本实现**输入什么日期就用什么日期**（可预期、不静默改数据），当小时填 `23` 时输入页会提示
「23时: 传统作次日子时」，要按传统起就把日期填成次日。

### 为什么是「输入时间」而不是「读系统时间」
Cardputer ADV 的核心是 **Stamp-S3A（ESP32-S3FN8）**，官方引脚表里只有 LCD / 音频 / IMU / IR /
电池 / 键盘 / microSD —— **没有 RTC 芯片**（`M5.Rtc.isEnabled()` 在这块板上为 false），
断电后系统时间必丢，也无法可靠自动对时。所以时间由用户当场输入；
输入页会做合法性校验（年 1900–2100、月 01–12、日按**真实历法**判当月天数含闰年二月、时 00–23、
公历日期须落在农历表覆盖范围内）。输入过程中**不透露卦象**，
本卦 / 动爻 / 之卦一律等到起卦结果页才揭晓。

### 校验脚本（三个，分工明确）
| 脚本 | 管什么 |
|---|---|
| `_lunar_table.py` | **农历表**：生成 `src/lunar_data.h`；三方数据比对 + ephem 实算朔时刻逐个裁决 2486 个初一 |
| `_scratch/verify_conv.py` | **转换实现**：把 `lunar.h` 的 `solarToLunar` 逐行照抄成 Python，与两个独立库逐日比对 73384 天 |
| `_time_check.py` | **起卦公式**：原书筮例 + 公历→农历基准点 + 完整链路 |

`_time_check.py` 用原书两个著名筮例当基准（日期是**农历**，原书如此）：

| 筮例 | 输入（农历 年支/月/日/时辰） | 本卦 | 动爻 | 之卦 |
|---|---|---|---|---|
| 观梅占 | 辰5 · 十二 · 十七 · 申9 | 泽火革 (49) | 初爻 | 泽山咸 (31) |
| 牡丹占 | 巳6 · 三 · 十六 · 卯4 | 天风姤 (44) | 五爻 | 火风鼎 (50) |

另含 13 个公历→农历基准点（4 个春节 + 3 个闰月初一 + 起止边界）、3 条公历→农历→卦完整链路、
年支（农历年）与时辰换算、64 卦 / 6 爻位可达性、闰年天数、输入串边界，以及分布粗查
（公历 2026 全年 4380 次起卦：64 卦全覆盖，动爻分布 730×6 完全均匀）。

## 数据来源（最全公开版）
- 站点：`gaodaoyiduan.org/original/` 的 64 个卦页（每卦含卦名释义、卦辞、《彖传》《大象》、
  六爻逐爻的「高岛占断」与「占例」，并含乾/坤的「用九/用六」）。
- 抓取：64 页 HTML 存于 `raw/`；`_build.py` 把每卦正文按 `h3`（爻题）切成 **7 段**，
  生成 `src/gddy_data.h`（**1.55 MB，448 段**）。
- 正文元素语义（解析要点，**别漏**）：
  | 标签 | 含义 |
  |---|---|
  | `h2` | 卦名 |
  | `h3` | **爻题**（`初九: 潜龙勿用。`）—— 分段的锚点 |
  | `h4` | 小节标题（`占` / `占例`）→ 文中渲染成 `【占】` |
  | `p` | 正文段落 |
  | `blockquote.border-l-4` | 引文（卦辞 / 《彖传》/《大象》/《象传》） |
  | `ul > li` | **「占」下的问答条目**（`问战征：…`） |
  > 首版解析只抓了 `h2|h3|h4|p|b`，结果 `<blockquote>` 没匹配上（`<b\b` 不匹配 `<blockquote>`）、
  > `<li>` 完全没抓 —— 表现为**「占」下面的内容整段消失**。现已补齐这两类。
- 清洗：剔除站点排版残留（字间孤立空格、`［82］` 式校勘编号）。

## 中文显示（关键技巧）
- **M5GFX 库自带简体中文 efont 点阵字库**（`lgfx::fonts::efontCN_12/14/16/24`），
  直接 `setFont(&lgfx::fonts::efontCN_14)` 即可显示中文。
- ⚠️ **但 efont 只收 GB2312 那一档（约 7500 字）**：本书正文里有 **163 个生僻字**
  （姤、夬、禴、繘…）它没有，而 M5GFX 遇到缺字会调 `drawCharDummy` 画一个**方块 □**。
  解法是从系统宋体点阵生成一份 u8g2 格式的**补字字体** `src/sup_font.h`，
  `drawTextOn()` 在 efont 查不到该码点时逐字切到补字字体绘制。
  （两档字号各 163 字形，共约 27KB Flash；整串不含缺字时直接走原 `drawString`，
  渲染结果与未打补丁时逐像素一致。）
- **几何对齐**（`_mkfont.py` 按此生成，否则字会错位）：
  `xo = 宋体墨迹左列 + 偏置`（14px 偏置 = 1、12px 偏置 = 0 —— 两档出自不同生成管线）、
  `w = 墨迹宽`、`yo = (ascent − 墨迹顶行) − 墨迹高`。
- **混排绘制时每段必须临时用 `\0` 截断**再 `drawString`：各段重编码后是紧挨着存在同一个
  缓冲区里的，只有整串末尾有终止符；不截断就会把「本段起点 → 整串末尾」整段重画一遍，
  表现为**字形上叠着一堆方块**。
- **改动文案后要重跑 `python _mkfont.py`**，否则新出现的生僻字仍是方块。
- 文本以 `const char*`（UTF-8）烧进 Flash，运行时按字数折行、分页滚动。
- 详目页行高在 `setup()` 里按 `fontHeight()` **实测**取值（并夹紧到 7 行刚好放得下），
  不写死，避免换字号后 7 行溢出屏幕。
- 详目条目名一行放不下时，**只有当前选中那条会滚**，其余条目静止截断成「前几字 + 省略号」。
- 滚动是**逐像素平滑滑动**（不是逐字跳跃）：把整名先画进一个 240×行高 的离屏缓冲
  （`LGFX_Sprite`），再按像素偏移从中切一条 `pushImage` 推上屏；节奏为
  **停 1.2s → 平滑滚到尾 → 停 0.9s → 平滑滚回 → 循环**，约 45px/s。
  位移时只重绘这一行，不整屏刷、不闪。缓冲分配失败会自动退化成静态截断显示。

## 环境准备（为什么项目里带 `boards/` 和 `variants/`）
Cardputer 的板型**不在**官方 `platform-espressif32` 里（6.5.0 和最新的 7.1.3 都查过，都没有），
M5GFX 的框架包里也不带 `m5stack_cardputer` 这个 variant。所以本项目把它们随源码一起带上：

- `boards/m5stack_cardputer.json` —— PlatformIO 会自动搜索**项目根**的 `boards/` 目录；
- `variants/m5stack_cardputer/pins_arduino.h` —— 靠板型 JSON 里的
  `"build.variants_dir": "variants"` 指定路径，框架的 `platformio-build.py` 会把它读成
  `$PROJECT_DIR/variants/`，**不需要往全局的 `framework-arduinoespressif32` 包里注入任何文件**。

所以 clone 下来直接 `pio run` 就行，不必手工配置平台。

## 构建与烧录
```bat
pio run                              # 编译  (Flash ~30%)
pio run -t upload                    # 烧录（插线；必要时按住侧面 G0/BOOT 进下载模式）
pio device monitor -b 115200         # 看串口

python _build.py                     # 需要时重建数据 raw/*.html -> src/gddy_data.h
python _verify.py                    # 校验数据(输出 _verify.out)
python _cast_check.py                # 校验数字卦换算(输出 _cast_check.out)
python _lunar_table.py --check       # 校验农历表(三方比对 + 朔时刻裁决; 去掉 --check 则重新生成)
python _time_check.py                # 校验时间卦换算(原书两个筮例, 全过才打印"全部通过")
python _mkfont.py                    # 改文案后重建补字字体 -> src/sup_font.h
```
> `_mkfont.py` / `_efont.py` 需要 Pillow；`_efont.py` 会从 `.pio/libdeps/` 里定位 efont 数据，
> 所以先跑一次 `pio run` 让依赖就位。
> `_lunar_table.py` 需要 `pip install lunardate lunar_python LunarCalendar ephem`
> （三个农历库 + 一个天文库，只在**生成 / 校验**表时用，固件本身零依赖，表已随源码提交）；
> `_scratch/verify_conv.py` 需要 lunardate + lunar_python。

## 在 velxio.dev 预览
velxio 的 Cardputer ADV 用同款 `M5Cardputer` 库，`src/main.cpp` 可直接粘进
`velxio.dev/editor/`（选 M5 Cardputer ADV）运行；`src/gddy_data.h` 也一并粘入 `src/` 即可。
注意 velxio 是否内置 efont 中文字库取决于其环境，若缺中文可改回 ASCII 提示或在该平台另行加载字库。

## 备注
- 枚举成员**别取名 `INPUT`**：Arduino 的 `esp32-hal-gpio.h` 把它 `#define` 成 `0x01`（GPIO 方向宏），
  当枚举名会报 `expected identifier before numeric constant`。本项目的数字输入页枚举名为 `INPUT9`。
- 全本《高岛易断》体量很大（原书数百页），这里收录的是「每卦完整占断」级文本；若想进一步
  精简体积，可在 `_build.py` 里只保留卦辞 + 六爻断语、去掉「占例」。
- 想更新/扩充数据：替换 `raw/` 下 HTML 后重跑 `_build.py` 即可（结构变了就同步改 `_verify.py` 的断言）。
- 乾/坤两卦的「用九 / 用六」并入「上九 / 上六」段落尾部，不单独占条目（保持恒为 7 项）。
